# Template: awesome-cv

- **Type:** CV
- **Source extension:** .tex
- **Engine/toolchain:** lualatex
- **Page limit:** 1 page (this repo's established single-page convention; the class itself defaults to no limit)
- **Fonts:** Roboto, bundled in `fonts/` (Regular/Italic/Bold/BoldItalic/Light/LightItalic .ttf). Source Sans 3 is also bundled (`fonts/SourceSans3-*.otf`, same six weights) because `awesome-cv.cls` unconditionally declares it as the document's main/sans font at class-load time - removing the files would make that declaration fail - but it must never actually be selected for visible text (see Known Pitfalls).
- **Class/packages:** `awesome-cv.cls` (bundled, from https://github.com/posquit0/Awesome-CV, LPPL v1.3c). Requires `enumitem`, `xifthen`, `ifmtarg`, `accsupp`, `tcolorbox`, `pgf`, `environ`, `trimspaces`, `tikzfill` - install with `tlmgr --usermode install <pkg>` if missing (this machine's TeX Live did not ship them; see Known Pitfalls for the exact commands used).

## Compile command

Run from `cv/` (the output directory), referencing this template folder by relative path so fonts/class files aren't duplicated per application:

    cd cv && rm -f <file>.pdf && mkdir -p build && TEXINPUTS=../templates/cv/awesome-cv//: OSFONTDIR=../templates/cv/awesome-cv/fonts lualatex -interaction=nonstopmode -output-directory=build <file>.tex && mv build/<file>.pdf ./

`TEXINPUTS` lets kpathsea find `awesome-cv.cls` without copying it into `cv/`. `OSFONTDIR` makes luaotfload discover the bundled Roboto/Source Sans 3 files without installing them system-wide. Both are required - a bare `lualatex <file>.tex` from `cv/` will fail to find the class and render with fallback fonts.

If a failed compile needs inspecting, the log is in `cv/build/<file>.log`.

## Style rules

- Section headers use `\cvsection{}` (auto-draws the accent-colored rule - don't add a manual `\hrule`). The class's default behavior only colors the first 3 characters of the heading (`acvSectionColorHighlight`'s `\StrSplit` trick) - overridden in the preamble (`\renewcommand*{\sectionstyle}...`) to color the whole heading instead.
- Experience/education entries use `\begin{cventries}...\end{cventries}` wrapping one or more `\cventry{title}{org}{location}{dates}{description}`; bullet lists inside a `\cventry`'s description go in `\begin{cvitems}...\end{cvitems}`.
- Free-form prose (the profile/summary statement) uses `\begin{cvparagraph}...\end{cvparagraph}`, not `cventries` - and has no `\cvsection{}` heading above it; the statement itself opens the CV directly under the header.
- `\tech{}` (defined in the template preamble) bolds and accent-colors a technology/architecture term - use it consistently in the profile statement and experience bullets, matching the `\tech{}` convention in the stock moderncv template (`cv/main_example.tex`).
- Accent color is a custom muted terracotta, `\definecolor{accentcolor}{HTML}{B3281C}` (softer than the built-in `awesome-*` swatches, which are all fully-saturated). `\colorlet{awesome}{accentcolor}` aliases it for the class's own internal single-level `\color{awesome}` calls (section headings, entry locations). To pick a different accent, change the hex value and keep the alias in sync.
- **Centered banner header** (`\customcvheader{<profile>}`, replaces the stock `\makecvheader[C]`): name (32pt, bold, one font group - see Known Pitfalls) and role (16pt bold, accent colour) centered; one centered contact line `address | email | phone | GitHub | LinkedIn` at 10pt (`\contactlinestyle`); one centered language line `Native: ... | Fluent: ...` (labels bold in the accent colour); then the profile statement full-width below, passed as the macro's one argument (no `\cvsection{}` heading). Each centered line is wrapped in `\mbox`, so a line that grows too long raises an overfull warning instead of wrapping silently. A multi-word surname goes entirely in `\name`'s second argument (e.g. `\name{Victor}{Martinez Montané}`) - the macro joins first and last in one font group. The gap between banner and profile is `\vspace{10pt}` (`\cvparagraph`'s own opening hook pulls up by ~1.2mm, so the visible gap is smaller than that number).
- `\github{}` / `\linkedin{}` take bare usernames, not full URLs (e.g. `\linkedin{jaster-victor}`, not a linkedin.com URL) - `\customcvheader` prepends the icon and base URL itself, same as the class's stock behavior.
- **There is no dedicated skills/competencies section.** Instead, every experience/project bullet ends with the technologies it used as colored pill tags (`\skillpill{<Skill>}`, built with `\newtcbox` - already-loaded `tcolorbox`; a pale tint of the accent color, `pillbg` `#F4E7E5`, with accent-colored text and rounded corners): write the bullet as a clean outcome sentence with no technology names in the prose, then append `. \skillpill{Rust} \skillpill{Postgres}` etc. after the period. List short, single-concept tags (`Tokio`, not `Tokio/Tower/Tonic/Axum async ecosystem`) - pills work best for single tags, not phrases. Separate pills with a **plain space**, never `\,` - see Known Pitfalls.
- **Body text (`\paragraphstyle`, `\descriptionstyle`) is bumped from the class's 9pt/1em (9pt leading - no extra line-height at all) to ~10.5pt/15pt** - the stock sizing read as too small/cramped to read comfortably. This eats noticeably more vertical space across the whole document (profile statement + every experience bullet + project descriptions), so the page-budget levers below were tightened to compensate and keep the result on one page: `\geometry{...}` left/right margins 1.4cm→1.1cm, `\acvSectionTopSkip` 3mm→2mm, `\acvSectionContentTopSkip` 2.5mm→1.8mm (both class-wide, affect every section), `\cventry`'s per-entry `\vspace` -2mm→-2.0mm (kept loose for readability between entries, at the cost of margin/other spacing elsewhere), `\cvitems`'s pre-bullet `\vspace` -4mm→-4.8mm, the header's contact-line gaps 4pt→2pt. If a tailored CV still overflows, tighten `\geometry{...}` margins further next before cutting content or shrinking the body text back down.
- **Entry title/role/location are all the same size.** The class's stock `\entrypositionstyle` (role) and `\entrylocationstyle` (location) are 8pt/9pt - visibly smaller than `\entrytitlestyle`'s (company name) 10pt. Overridden to 10pt to match.

## Known pitfalls

- **Never call `\sffamily`, `\rmfamily`, or `\normalfont` directly, and never reintroduce `\setmainfont`/`\setsansfont{Source Sans 3}` as the active body font.** `awesome-cv.cls`'s default body/footer font is Source Sans 3 via `\bodyfont`/`\bodyfontlight`, and that font - at any weight - drops nearly every interword space from the PDF's text layer under `pypdf` extraction (e.g. "I'm a Senior Software Engineer" extracts as "I'maSeniorSoftwareEngineer..."). Confirmed on upstream Awesome-CV's own unmodified example, so it's an upstream font/shaping interaction, not something specific to this repo's content. `pdftotext` extracts the same PDF with spaces intact, so it's invisible on the rendered page and to a human reviewer - only naive/literal text extractors (which `pypdf` is, and which some real ATS parsers are) are affected. The template's preamble works around it by overriding the class's own font hooks to Roboto instead (`\renewcommand*{\bodyfont}{\roboto\selectfont}`, `\renewcommand*{\bodyfontlight}{\roboto\fontseries{l}\selectfont}`, `\renewcommand*{\footerfont}{\roboto\selectfont}}`) - Roboto was verified clean under both extractors, including long, multi-line, fully-justified paragraphs. Keep these three overrides in any tailored CV; don't delete them to "simplify" the preamble.
- **Splitting a name (or any short run) across two separate font-selection groups silently drops the space between them from the PDF text layer - in both `pypdf` AND `pdftotext`.** This is different from the other quirks here: it's not a naive-extractor artifact, the space is genuinely absent from the exported text even though the page renders with a normal-looking gap. Found when the header's first/last name were built as two calls (`\headerfirstnamestyle{...}` then `\headerlastnamestyle{...}`, each its own `{...}` group) - even with *identical* color and weight, "Victor Martinez" extracted as "VictorMartinez". Fixed by building the whole name as a single inline style wrapping both words in one group (`{\addfontfeature{Kerning=Off}\fontsize{32pt}{1em}\headerfont\bfseries\color{text} \@firstname\ \@lastname}` in `\customcvheader`) instead of calling `\headerfirstnamestyle`/`\headerlastnamestyle` separately. Keep any multi-word styled run (names, short labels) in one group; don't split it across macro calls even for a purely cosmetic reason.
- **Use `\textcolor{accentcolor}{...}` (the literal color name), never `\textcolor{awesome}{...}` (the `\colorlet` alias), for inline highlighted text.** `\tech{}` already does this correctly. Nesting `\textcolor` with a `\colorlet` alias inside already-colored body text (e.g. inside a `\cvitems` bullet, which is already colored by `\descriptionstyle`) leaks the literal alias name into the PDF text layer under `pdftotext` extraction - e.g. a bullet highlighting "Rust" extracted as "awesomeRust". The class's own internal single-level `\color{awesome}` calls (section headings, entry locations, etc.) are unaffected - this is specific to nested `\textcolor` with an alias.
- **`\tech{}` must keep `Kerning=Off`.** Isolated testing showed `\textbf` alone (not `\textcolor`) was the actual trigger for a worse version of the extraction bug: Roboto Bold's own kerning pairs (e.g. the "To" pair) get exported as a PDF positioning adjustment that `pypdf` misreads as a word-internal space ("Tokio" -> "T okio"), and the interword space immediately *after* a bolded run could vanish the same way ("Tokio runtime" -> "Tokioruntime", a real ATS-breaking token merge, not just cosmetic). `\tech{}`'s definition wraps its content in `\addfontfeature{Kerning=Off}` to fix this - don't remove it.
- **Residual, accepted quirk:** `pypdf` still occasionally inserts an extra space right after an opening parenthesis when it's immediately followed by a `\tech{}`-highlighted term (e.g. "(Tokio, Apalis)" extracts as "( Tokio, Apalis)"). Unlike the bug above, this doesn't merge or split any individual keyword - only a stray leading space before the term. Confirmed `Kerning=Off` (scoped or applied to the whole body font) does not fix this one; root cause looks like an `xcolor` marked-content artifact specific to a color switch landing right after `(`, independent of bold. `pdftotext` is unaffected. Same risk tier as the single-word quirk already accepted in the stock moderncv template (`cv/main_example.tex`) - not worth chasing further.
- **Several CTAN packages this class requires were missing from this machine's TeX Live** (`enumitem`, `xifthen`, `ifmtarg`, `accsupp`, `tcolorbox`, `pgf`, `environ`, `trimspaces`, `tikzfill`) and had to be installed into a user texmf tree, since the system TeX Live install (a read-only Nix store path) can't be modified directly:
  ```
  tlmgr init-usertree
  tlmgr --repository https://texlive.info/tlnet-archive/<YYYY>/<MM>/<DD>/tlnet --usermode install <package names>
  ```
  Use the date matching the installed TeX Live revision (`tlmgr version`) - `tlmgr`'s default CTAN mirror refuses cross-release installs once a newer TeX Live has been released. If `lualatex` reports a different missing `.sty` on a fresh machine, install it the same way.
- `\address{}` must not be left empty/deleted the way the moderncv template's docs warn about for its own `\address{}{}{}` - this class's single-argument `\address{...}` has not been tested empty; always pass the "City, Country (Remote)" string.
- **Separating `\skillpill{}` calls with `\,` (a fixed, non-breaking thin space) instead of a plain space makes a whole run of pills a single unbreakable unit**, which can overflow past the text column with no line break - LaTeX doesn't clip overflowing content, it just lets it draw over whatever's below/beside it. This was most visible when pills lived in a narrow `cvskills` column (a long pill row had nowhere to wrap and bled into the neighboring column), but the same risk applies to a long pill run after a bullet if a future edit crams in many tags. Always use a plain space between `\skillpill{}` calls, never `\,`.
- **This template has no footer** (no date/name/page number): `\makecvfooter` is deliberately not called, and the class clears the footer by default, so omitting it is enough. The note below only matters if a footer is re-enabled.
- **Footer clipped at the page bottom when `bottom` ≤ `footskip`.** The footer baseline sits one `footskip` below the text area, so with `bottom` equal to `footskip` (e.g. both 0.5cm) the baseline lands exactly on the page edge and the footer's lower ~1.7pt falls off the page (measured with `pdftotext -bbox`: footer yMax 843.6pt on an 841.9pt page). Keep `bottom` clearly larger than `footskip` - the CV uses `bottom=1.0cm`, `footskip=.5cm`, which puts the footer ~12pt inside the edge. When tightening margins to fit a page, shrink `top`/left/right or content first and re-check the footer with `pdftotext -bbox`.
- **Neither bundled font has Unicode geometric shapes** (e.g. U+25CF `●`, U+25CB `○`). Typing them literally compiles without error but silently drops the glyph ("Missing character" in the log, nothing visible) - lualatex doesn't fail loudly on a missing glyph. If a symbol is ever needed, draw it (TikZ) or pick a font that has it, and check the compile log for "Missing character" whenever adding a new symbol/icon.

## Output file

`cv/main_<company>_<role>.tex`. Do not copy `awesome-cv.cls` or the `fonts/` folder into `cv/` - the compile command above reaches them via `TEXINPUTS`/`OSFONTDIR` relative paths instead, so every tailored CV stays a single file.
